OpenSpace Project Plan

Programmable AI Team OS 的交付路线

OpenSpace 的规划围绕一个主线展开：用户只需要设定 Goal，系统自动组织 AI Team、Workflow、知识沉淀和能力进化，让本地 AI 协作从聊天变成可编排的团队操作系统。

Goal First Team Driven Workflow OS Knowledge Loop Local First
1

产品定位

OpenSpace 是 Programmable AI Team OS：不是普通聊天壳，而是围绕 Goal、Team、Workflow 和 Knowledge 运转的本地 AI 协作系统。

2

当前状态

Sprint 1 到 Sprint 7 已完成，MVP 已具备项目创建、AI 团队组建、Workflow 执行、批准流、沉淀、评估和团队协作式流程设计。

3

下一阶段

Sprint 8+ 聚焦真实任务体验、即时学习回路、团队级健康视图和 Worktree 隔离，让系统在日常开发中持续变可靠。

六层架构

层级 职责 代表能力

Layer 2: Team 团队成员 Team Architect、Facilitator、Agent Profile

已交付路线

Sprint 1-3：协作骨架

  • Foundation + Goal → AI Team：从目标生成可用团队。
  • Workflow Framework：YAML 工作流可被触发、分步执行并完结。
  • Responsibility + User Intervention：批准流、用户评论、override、abort、导入导出。

Sprint 4-5：学习闭环

  • Delivery Loop：Scribe 从 thread 中提炼 decisions 和 lessons。
  • Evolution Loop：Evaluator 和 Coach 基于表现提出 Agent description 修改建议。
  • Intelligence Tab：让用户审批、回看和应用沉淀。

Sprint 6-7：团队智能

  • Onboarding Loop：新项目自动分析，生成项目画像和推荐任务。
  • Skill Matrix：统计 tool_call，形成 Agent 能力地图。
  • Team-First Workflow Design：Facilitator 主持团队讨论并产出 workflow draft。

Sprint 4-ext：Runtime 旁路

  • CursorSdkAdapter 与 CLI Adapter 并存。
  • OPENSPACE_CURSOR_BACKEND=sdk|cli 可切换。
  • 统一 tool use 解析与 Activity 摘要。

近期验收重点

  • 真实开发任务中，用户可以快速判断 Agent 是否靠谱。
  • 反馈能够低摩擦进入系统，并转化为后续上下文或 Agent 修改建议。
  • 长输出、失败、卡住、取消和重试的体验足够明确。
  • 多个 Agent 并行时，工作区变更不会相互踩踏。

工程约束

  • 保持本地优先：SQLite、Fastify、WebSocket、CLI / SDK Adapter。
  • Project 是隔离边界：上下文、任务、知识和 workflow 都按 Project 组织。
  • Agent 不拥有独立 workspace；并发隔离优先通过 Worktree 解决。
  • 新增能力必须回到 Goal → Team → Workflow → Knowledge → Capability 主线。

当前一句话目标

MVP 已完成后，OpenSpace 的下一步不是堆更多按钮，而是把真实任务中的反馈、学习、团队状态和并发安全跑顺，让 AI Team 在项目里越用越懂上下文。
